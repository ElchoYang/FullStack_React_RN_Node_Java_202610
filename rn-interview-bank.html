1 · Vue / Web → RN 迁移对照表 先背这张

Vue / WebRN / Expo关键差异（面试最爱问）
template + v-if/v-forJSX + 条件表达式 / .map()没有指令，全是 JS 表达式
ref/reactive 响应式useState + 不可变更新不侦测对象内部修改，必须返回新引用
watch/onMounted/onUnmounteduseEffect(fn, deps)依赖数组决定时机，return 做清理
computeduseMemo/useCallback缓存值与函数引用，减少重渲染
CSS / <style scoped>StyleSheet.create + style无级联、无继承、无单位数字、无伪类
div/span/pView/Text文字必须包 Text，否则直接报错
imgImage/expo-image必须给宽高（尤其远程图）否则不渲染
overflow:scrollScrollView一次性渲染全部子项，长列表禁用
v-for + 虚拟滚动库FlatList/FlashList20 条以上优先 FlashList
@clickonPress（Pressable）没有 onClick，没有 DOM 冒泡体系
vue-router / Nuxt pages/Expo Router 的 app/文件路由几乎同构：[id].tsx ≈ [id].vue
router.push/route.paramsrouter.push/useLocalSearchParams()参数是 URL 的一部分，支持深链接
Pinia / VuexZustand / Jotai管客户端状态
VueQuery / SWRTanStack Query管服务端状态：缓存、重取、乐观更新
localStorageAsyncStorage异步、明文、不适合敏感数据
—expo-secure-storeKeychain / Keystore，用来存 token
Vite / WebpackMetroFast Refresh ≈ HMR
Chrome V8HermesRN 默认 JS 引擎，优化移动端启动
npm run dev + 浏览器npx expo start + Expo Go跑真机/模拟器，没有 DOM / window
浏览器 CORSRN 无 CORS但 Android 9+ 禁明文 HTTP，iOS 有 ATS
前端构建部署EAS Build / Submit / UpdateOTA 只能更 JS 与资源，不能更原生代码
.env / import.meta.envEXPO_PUBLIC_*会打进客户端包，绝不能放密钥

3 · Vue 转 RN 十大高频坑 要能讲「为什么」

#坑一句话原因
1元素没并排RN flexbox 默认 column，Web 默认 row
2裸文字报错文本必须包在 <Text> 内，没有 DOM 文本节点
3图片不显示Image 无固有尺寸，远程图必须给宽高
4父样式不生效无级联、无继承（Text 嵌套 Text 是例外）
5setState 后读到旧值闭包快照 + 批处理，用函数式更新 / useEffect
6数组改了 UI 不变直接改原数组引用没变，必须返回新数组
7useEffect 死循环依赖里放了每次新建的对象/数组，或漏依赖
8长列表卡死用 ScrollView 渲染几千条；换 FlashList
9window/localStorage 报错RN 不是浏览器，换 useWindowDimensions/AsyncStorage
10OTA 更新后原生功能没变OTA 只更 JS 与资源，原生改动必须重新构建

5 · 没做过 RN 项目怎么答 优先级最高

H1 可直接背诵：
「我确实是 RN 新手，没有上线的 RN 项目，这点我不绕。但我有 X 年 Vue / Web 项目经验，做过完整的页面路由、状态管理、接口封装和权限流程。RN 的这些概念和 Vue 是一一对应的：Expo Router 对应 Nuxt 的文件路由，Zustand 对应 Pinia，React Query 对应 VueQuery，Metro/EAS 对应 Vite/构建发布。我已经系统学过 RN，重点补了三块 Web 里没有的东西：原生权限与平台差异、无 DOM/CSS 的样式与布局体系、以及 JS 线程与 UI 线程分离带来的性能模型。我预期上手的主要风险在原生配置和真机调试，所以会先从 Expo 托管工作流切入，遇到原生需求再用 config plugin 处理。如果可以，我愿意现场写一个带列表、详情和表单提交的小 demo 来验证。」

结构：① 不撒谎不编项目 ② 用对照表把旧经验折算成新能力 ③ 明确说出「我知道自己缺什么」 ④ 给可验证的落地方案

不要说

  • 「我做过 RN 项目」（追问细节会穿帮）
  • 「RN 和 Vue 差不多，很容易」
  • 「性能应该没问题吧」
  • 「遇到问题搜一下就行」
  • 编造线上事故 / 性能调优战绩

要说

  • 「没有上线项目，但系统学习过并做了迁移与 demo 验证」
  • 「状态与路由能迁移；原生边界、双线程、发布方式是我重点补的三块」
  • 「掉帧要先定位是 JS 线程还是 UI 线程」
  • 「排查顺序：清 Metro 缓存 → 日志/DevTools → 缩小到平台或原生配置 → expo-doctor 查兼容」
  • 用「我预判到的坑 + 会在 demo 里验证」体现工程意识

「你遇到过什么坑」诚实版：「目前没有线上 RN 项目，所以没有真实事故可讲。但学习时我特意整理了 Vue 转 RN 最易错的点：flex 默认方向、文字必须包 Text、Image 必须给尺寸、样式不继承、setState 的闭包快照、长列表不能用 ScrollView，写 demo 时会优先验证。遇到原生配置类问题，我会先看 app.json / config plugin 与平台差异，再用 expo-doctor 查版本兼容。」

6 · Node.js 八条速记 Web 背景可直接迁移

  1. 分层：router → controller → service → repository，别在路由里写业务。
  2. 校验：Zod/Joi 在边界校验；统一错误响应 { code, message, traceId }。
  3. 鉴权：access 短 + refresh 长、轮换 + jti 防重放；RBAC 放中间件。
  4. 上传：流式 multipart / 预签名直传；禁 base64；分片 + 幂等 key + 秒传。
  5. 进度：SSE（单向）优先于 WebSocket（双向），轮询最差。
  6. 稳定性：限流 429、超时、重试退避、结构化日志 + traceId、健康检查。
  7. 配置：密钥只在服务端 env / EAS Secrets；EXPO_PUBLIC_* 一律视为公开。
  8. 联调部署：后端绑 0.0.0.0、adb reverse / 局域网 IP、HTTPS；Docker + PM2 + 灰度。
