1. Podman 基础

1.1 Podman 是什么

Podman（Pod Manager）是 Red Hat 主导开发的开源容器引擎，用于运行、构建和管理 OCI 标准容器。它解决的问题和 Docker 一样，但架构不同：

对比项PodmanDocker
架构无守护进程（daemonless），每条命令直接由进程执行依赖常驻 dockerd 守护进程
权限模型原生支持 rootless（非 root 运行），更安全rootless 是后期补充，功能受限
CLI 兼容alias docker=podman 几乎无感迁移—
Pod 概念原生支持 Pod（多容器共享网络/存储命名空间）无（K8s 层面才有）
Systemd 集成可生成 systemd unit 管理容器需第三方工具
图形界面Podman Desktop（开源免费）Docker Desktop（商用需付费授权）
Windows 实现WSL2 中跑 Linux 虚拟机（podman machine）WSL2 / Hyper-V

关键特性：

  • 无守护进程：没有单点故障的后台进程，podman ps 直接与容器运行时（crun/runc）交互。
  • Rootless 优先：默认以普通用户身份运行容器，容器内 root 映射为宿主机普通用户，逃逸风险低。
  • OCI 兼容：镜像格式、CLI 命令与 Docker 完全兼容，可直接从 Docker Hub 拉取镜像。
  • 内置 Compose 支持：Podman 5.x 自带 podman compose，可调用外部 docker-compose 或 podman-compose。

1.2 核心概念

概念说明
镜像（Image）只读模板，分层存储，OCI 格式
容器（Container）镜像的运行实例，读写层叠加在镜像之上
Pod一个或多个容器的组合，共享同一网络命名空间（同一 IP）、可共享卷。Podman 特有，向 Kubernetes 对齐
卷（Volume）持久化数据存储，生命周期独立于容器
网络Podman 5 使用 Netavark 作为网络栈（替代 CNI），默认创建 podman bridge 网络
podman machineWindows/macOS 上管理 Linux 虚拟机的工具，容器实际跑在这个虚拟机里

1.3 Windows 上的架构（重要）

在 Windows 上，Podman 不是原生运行的：

Windows 宿主机
 └─ Podman Desktop（GUI，Electron 应用）
     └─ podman.exe（CLI 客户端）
         └─ podman machine（WSL2 虚拟机 "podman-machine-default"）
             └─ Linux 容器（crun 运行时、Netavark 网络、Podman 引擎）
理解这一点非常重要，它决定了后面所有"注意事项"：
  1. 容器跑在 WSL2 虚拟机里，虚拟机不启动，一切命令都会失败（报 dial unix /run/podman/podman.sock: connect: no such file or directory）。
  2. 卷挂载的路径是虚拟机视角的路径，不是 Windows 路径。
  3. 虚拟机默认资源有限（通常 4GB 内存），跑 Spring Boot + MySQL 需要调大。

2. Podman CLI 常用命令

# ===== 机器管理（Windows/macOS）=====
podman machine init --memory 8192 --cpus 4 --disk-size 60   # 初始化虚拟机（调大资源）
podman machine start                                        # 启动虚拟机
podman machine stop                                         # 停止虚拟机
podman machine list                                         # 查看虚拟机状态

# ===== 镜像 =====
podman pull eclipse-temurin:21-jre                          # 拉取镜像
podman images                                               # 列出镜像
podman rmi <镜像ID>                                          # 删除镜像
podman build -t myapp:1.0 .                                 # 构建镜像
podman tag myapp:1.0 registry.example.com/myapp:1.0          # 打标签
podman push registry.example.com/myapp:1.0                   # 推送
podman save -o myapp.tar myapp:1.0                          # 导出镜像
podman load -i myapp.tar                                    # 导入镜像

# ===== 容器 =====
podman run -d --name web -p 8080:8080 myapp:1.0             # 后台运行
podman run -it --rm alpine sh                               # 交互式运行，退出即删
podman ps                                                   # 运行中的容器
podman ps -a                                                # 全部容器（含已停止）
podman logs -f web                                          # 跟踪日志
podman exec -it web bash                                    # 进入容器
podman stop web / podman start web / podman restart web      # 生命周期
podman rm web                                               # 删除容器
podman inspect web                                          # 查看详细配置
podman stats                                                # 实时资源占用

# ===== Pod =====
podman pod create --name mypod -p 8080:8080                 # 创建 Pod 并映射端口
podman run -d --pod mypod myapp:1.0                         # 把容器加入 Pod
podman pod ps                                               # 列出 Pod
podman pod stop mypod && podman pod rm mypod                # 停止并删除整个 Pod

# ===== 卷 =====
podman volume create appdata                                # 创建命名卷
podman volume ls / podman volume inspect appdata             # 查看
podman volume rm appdata                                    # 删除

# ===== 清理 =====
podman system prune                                         # 清理无用容器/网络/悬空镜像
podman system prune -a --volumes                            # 深度清理（危险，会删全部未用镜像和卷）
podman system df                                            # 查看磁盘占用

# ===== Docker 兼容 =====
podman compose up -d                                        # 用 compose 文件编排（Podman 5 内置）
记忆技巧：把 docker 换成 podman，90% 的命令一模一样。

3. Podman Desktop 操作指南

Podman Desktop 是管理 Podman 的图形界面（Electron 应用），左侧边栏就是它的功能地图，对应 v1.30.5 的界面。

3.1 安装与初始化

# 1. 安装 Podman Desktop（二选一）
winget install -e --id RedHat.Podman-Desktop
# 或从官网 https://podman-desktop.io 下载安装包

# 2. 在 Podman Desktop 内安装 Podman 引擎
# 首次启动会提示 "Install Podman"，点击即可（等价于 winget install RedHat.Podman）
# 也可以手动：winget install -e --id RedHat.Podman

# 3. 初始化并启动虚拟机
podman machine init --memory 8192 --cpus 4 --disk-size 60
podman machine start
前置条件：Windows 10/11 需启用 WSL2。管理员 PowerShell 执行 wsl --install 后重启。Podman Desktop 检测到 WSL 缺失时也会引导你开启。

3.2 界面模块速查（对应左侧边栏）

模块功能常用操作
Dashboard总览：引擎状态、CPU/内存占用、快捷入口启动/停止 podman machine；查看 Explore Features 教程卡片
Containers容器列表启动/停止/删除、查看日志（Logs 标签）、打开终端（Terminal 标签）、点击端口直接在浏览器打开服务
PodsPod 列表创建 Pod、展开查看 Pod 内每个容器、Kube 化（生成 K8s YAML）
Images镜像列表拉取镜像（Pull）、从 Containerfile 构建（Build）、运行镜像成容器、推送到仓库
Volumes卷管理创建/删除卷、查看卷的挂载点（挂载点在 WSL 虚拟机内）
Networks网络管理查看/创建网络（Netavark），排查容器间通信问题
Secrets密钥管理存放 API Key、数据库密码等敏感信息，供容器引用
KubernetesK8s 集成连接 kind/minikube 等本地集群，用 Podman 直接跑 YAML（podman play kube）
Extensions扩展管理安装扩展增强功能，如 Podman AI Lab（本地大模型实验）等

3.3 典型操作流程：跑起一个 Nginx

  1. 拉镜像：左侧 Images → 右上 Pull → 输入 docker.io/library/nginx:alpine → Pull。
  2. 运行：镜像列表找到 Nginx → 点 ▶ Run（或 Advanced 展开更多参数）→ 设置端口映射 8080:80、可选挂载卷。
  3. 验证：Containers 页面看到容器 Running，点击端口 8080 直接在浏览器打开。
  4. 看日志/进终端：点进容器详情 → Logs 看输出、Terminal 执行命令。
  5. 清理：容器停止后点删除；Images 页删除不用的镜像。

3.4 必须知道的设置

① Docker 兼容（Settings → Compatibility / Docker Compatibility）

开启后，Podman 会创建一个 Docker 兼容的命名管道套接字（Windows 上是 npipe:////./pipe/docker_engine），让原本只认 Docker 的工具（Maven 插件、IDE、docker compose 等）无感切换到 Podman。Spring Boot 开发强烈建议开启。

② 终端里保持连接：每次重启电脑后，需要先启动虚拟机：

podman machine start     # 或者在 Dashboard 页面点 Start

4. Spring Boot + Podman 实践

4.1 前置配置（Windows 一次性准备）

# 1. 调大虚拟机资源（跑 Spring Boot + MySQL 建议 8G）
podman machine stop
podman machine set --memory 8192 --cpus 4   # 部分版本需重新 init
podman machine start

# 2. 开启 Docker 兼容（Podman Desktop: Settings → Docker Compatibility → 打开开关）

# 3. 验证 docker 命令是否可用（开了兼容后）
docker version    # Server 显示 podman 即成功

4.2 编写 Dockerfile（分层构建，充分利用缓存）

Spring Boot 3.3+ 推荐分层 jar 方式：依赖层不常变、代码层常变，重建镜像时只重新打包代码层：

# ---- 构建阶段 ----
FROM maven:3.9-eclipse-temurin-21 AS build
WORKDIR /app
COPY pom.xml .
# 先拷 pom 下载依赖，利用镜像层缓存（代码改动不会重新下载依赖）
RUN mvn dependency:go-offline -B
COPY src ./src
RUN mvn package -DskipTests -B

# ---- 运行阶段（只用 JRE，镜像更小）----
FROM eclipse-temurin:21-jre-alpine
WORKDIR /app
RUN addgroup -S spring && adduser -S spring -G spring
USER spring
COPY --from=build /app/target/*.jar app.jar
EXPOSE 8080
# 容器感知 JVM 参数：按容器内存配额自动设置堆上限
ENTRYPOINT ["java", "-XX:MaxRAMPercentage=75.0", "-jar", "app.jar"]

构建并运行：

podman build -t myapp:1.0 .
podman run -d --name myapp -p 8080:8080 \
  -e SPRING_PROFILES_ACTIVE=prod \
  myapp:1.0
curl http://localhost:8080/actuator/health

4.3 三种构建集成方式

方式说明推荐度
podman build（CLI / Desktop）手动 mvn package 后 podman build，简单直接★★★★★
fabric8 docker-maven-pluginmvn package docker:build 一键构建，通过 Docker 兼容套接字连接 Podman★★★★☆
Jib无需 Dockerfile，但输出 tar 后需 podman load（或推 registry），多一步★★★☆☆
Buildpacks（pack build）零 Dockerfile，需配置 DOCKER_HOST 指向 Podman★★★☆☆

方式一：fabric8 docker-maven-plugin（最贴合 Maven 工作流）

<plugin>
    <groupId>io.fabric8</groupId>
    <artifactId>docker-maven-plugin</artifactId>
    <version>0.45.1</version>
    <configuration>
        <images>
            <image>
                <name>myapp:${project.version}</name>
                <build>
                    <from>eclipse-temurin:21-jre-alpine</from>
                    <assembly><descriptorRef>artifact</descriptorRef></assembly>
                    <entryPoint>java -XX:MaxRAMPercentage=75.0 -jar /maven/${project.build.finalName}.jar</entryPoint>
                    <ports><port>8080</port></ports>
                </build>
                <run><ports><port>8080:8080</port></ports></run>
            </image>
        </images>
    </configuration>
</plugin>
mvn package docker:build          # 构建（走 Docker 兼容套接字）
mvn docker:run                    # 启动

方式二：Jib

mvn compile jib:buildTar -Dimage=myapp:1.0   # 生成 target/jib-image.tar
podman load -i target/jib-image.tar

4.4 Compose 编排（Spring Boot + MySQL + Redis）

compose.yaml 放在项目根目录：

services:
  app:
    image: myapp:1.0
    build: .
    ports:
      - "8080:8080"
    environment:
      SPRING_DATASOURCE_URL: jdbc:mysql://db:3306/demo?useSSL=false
      SPRING_DATASOURCE_USERNAME: root
      SPRING_DATASOURCE_PASSWORD: secret
      SPRING_DATA_REDIS_HOST: cache
    depends_on:
      db:
        condition: service_healthy
      cache:
        condition: service_started

  db:
    image: mysql:8.4
    environment:
      MYSQL_ROOT_PASSWORD: secret
      MYSQL_DATABASE: demo
    ports:
      - "3306:3306"
    volumes:
      - dbdata:/var/lib/mysql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-psecret"]
      interval: 5s
      timeout: 3s
      retries: 10

  cache:
    image: redis:7-alpine
    ports:
      - "6379:6379"

volumes:
  dbdata:
podman compose up -d      # Podman 5 内置 compose 支持（调用 docker-compose 或 podman-compose）
podman compose logs -f app
podman compose down       # 停止并删除（数据卷保留）

Spring Boot 自带的 docker-compose 集成也兼容 Podman（只要 Docker 兼容套接字开着）：

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-docker-compose</artifactId>
    <scope>runtime</scope>
</dependency>
# application-dev.yaml：本地开发时自动起依赖容器
spring:
  docker:
    compose:
      file: compose.yaml
      lifecycle-management: start-and-stop   # 应用退出时自动停容器

本地直接跑 SpringApplication，它会自动读取 compose.yaml 帮你把 MySQL/Redis 拉起来——开发体验极好。

4.5 注意事项清单（踩坑点）

🌐 网络与端口

  • 1. 端口映射语法不变（-p 8080:8080）。rootless 模式绑定 >1024 的端口无任何限制，8080/8443 随便用；绑定 80/443 等特权端口需 rootful 虚拟机（podman machine set --rootful）。
  • 2. 容器间通信用服务名：compose 网络内用 jdbc:mysql://db:3306（服务名），不要用 localhost——localhost 指容器自己。
  • 3. Windows 浏览器访问用 localhost：Podman machine 自动做了端口转发，localhost:8080 直接可用。

💾 存储与卷

  • 4. 优先用命名卷（-v dbdata:/var/lib/mysql），少用 bind mount。Windows 路径 bind mount（-v F:/data:/data）跨 WSL 文件系统走 9p 协议，性能差且权限易出问题；把 MySQL data 目录挂到 Windows 路径会直接报权限错误。
  • 5. bind mount 写 inode/原子重命名（如日志滚动、临时文件）在 Windows 挂载路径上不可靠。Spring Boot 日志输出到容器内路径再用卷，不要挂到 Windows 目录。
  • 6. Linux 上部署时的 SELinux：-v ./data:/data:z（本机 Windows 开发可忽略，部署到 RHEL/CentOS 时必须加 :z 或 :Z）。

⚙️ JVM 与资源

  • 7. 容器感知：JDK 10+ 自动感知 cgroup 内存限制，配合 -XX:MaxRAMPercentage=75.0 留出元空间和线程栈余量，避免容器被 OOM Kill。
  • 8. 虚拟机内存是硬上限：所有容器共享 podman machine 的内存（默认 4GB），Spring Boot + MySQL + Redis 同时跑很容易顶满，按 4.1 节调大到 8GB。
  • 9. 限制容器资源：podman run -m 1g --cpus 1 给容器设上限，防止单个容器拖垮整个虚拟机。

🔄 生命周期

  • 10. 每次重启电脑先 podman machine start，否则所有命令报 socket 连接失败。可在 Settings 里开启开机自动启动。
  • 11. 虚拟机停止后容器全部停止，但数据和镜像不会丢（存在虚拟机磁盘里）；只有 podman machine rm/reset 才会清空。
  • 12. 重启策略：--restart=always 在本机 machine 环境下意义有限（虚拟机不启动容器不会自启），正式环境交给 systemd 或 K8s。

🈶 时区与编码（中文环境必踩）

  • 13. 镜像默认 UTC 时区，日志时间差 8 小时。解决：-e TZ=Asia/Shanghai，并在 JDBC URL 加 serverTimezone=Asia/Shanghai。
  • 14. Alpine 基础镜像缺中文字体：用 POI/iText 导出 PDF/Excel 含中文时，需在 Dockerfile 里安装字体（apk add font-noto-cjk）。

🧹 其他

  • 15. 镜像源加速：国内拉 Docker Hub 慢，在 Settings → Registries 配置镜像加速地址，或改虚拟机内 /etc/containers/registries.conf。
  • 16. podman system prune 是把双刃剑：默认不清卷，但 -a --volumes 会删掉所有未使用镜像和卷（包括数据库数据），慎用。
  • 17. 健康检查：compose 里给 MySQL 加 healthcheck + depends_on.condition，否则 Spring Boot 先于 MySQL 起来会连接失败重试。

5. 常见问题 FAQ

Q1：Error: unable to connect to Podman socket？
虚拟机没启动。执行 podman machine start，或在 Dashboard 点 Start。

Q2：docker 命令报找不到 daemon？
Docker 兼容没开启。Settings → Docker Compatibility 打开开关，重启终端。

Q3：MySQL 容器一启动就退出，日志报权限错误？
用了 Windows 路径 bind mount。改用命名卷 dbdata:/var/lib/mysql。

Q4：容器里访问外网慢/失败？
公司代理没传进虚拟机。Settings → Proxy 配置代理，重启 machine。

Q5：Spring Boot 容器日志中文乱码？
加 JVM 参数 -Dfile.encoding=UTF-8（JDK 18+ 默认 UTF-8，一般无需设置），并确认 -e LANG=C.UTF-8。

Q6：怎么把本地镜像给别人？
podman save -o myapp.tar myapp:1.0 → 拷贝 tar → 对方 podman load -i myapp.tar。
